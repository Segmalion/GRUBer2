# release-build

Собирает Release-версии `GRUBer.exe` и `DeviceLister.exe`, раскладывает их в
`D:\UsersFiles\JOB-PROJECTS\TEST\GRUBer-RELEASE\[GRUBer_<версия>][DL_<версия>][<коммит>]\`
и подписывает оба файла сертификатом (thumbprint `B4D511E8418E0957521FE045EAAB39BA72B70F18`).

Перед сборкой обязательно проверяет состояние git (коммит/пуш) и спрашивает пользователя,
что делать, если рабочее дерево не в чистом/запушенном состоянии — иначе версия/коммит в
имени папки и в `GitVersion.h` (см. `tools\gen_gitversion.bat`) не будут отражать то, что
реально попадёт в релиз.

## Шаги

### 1. Проверка коммита

Выполнить `git status --porcelain` в корне репозитория.

- Если вывод пустой — рабочее дерево чистое, перейти к шагу 2.
- Если есть незакоммиченные изменения — показать пользователю краткую сводку `git status` и
  задать `AskUserQuestion`:
  - **Закоммитить сейчас** — застейджить релевантные файлы (не слепой `git add -A`; изучить
    `git status`/`git diff`, исключить мусор и файлы с потенциальными секретами по общему
    git-протоколу), сгенерировать краткое сообщение коммита по содержимому диффа (без
    дополнительных вопросов пользователю про текст сообщения — это уже решено), закоммитить с
    атрибуцией Claude из системного промпта этой сессии.
  - **Собирать как есть (dirty build)** — предупредить, что итоговый exe получит суффикс
    `-dirty` в версии из `GitVersion.h`, продолжить без коммита.
  - **Отменить** — остановить выполнение скилла.

### 2. Проверка пуша

Выполнить `git fetch` (только чтение, безопасно без подтверждения), затем проверить, сколько
локальных коммитов впереди апстрима: `git rev-list @{u}..HEAD --count`. Если апстрим не
настроен — считать это как "не запушено".

- Если коммитов впереди 0 — перейти к шагу 3.
- Если >0 (или апстрима нет) — задать `AskUserQuestion`:
  - **Запушить сейчас** — `git push` (на текущую ветку/апстрим; если апстрима нет —
    `git push -u origin <текущая ветка>` после подтверждения имени ветки/remote с пользователем).
  - **Продолжить без пуша** — собирать локально, не отправляя коммиты в remote.
  - **Отменить** — остановить выполнение скилла.

### 3. Сборка и подпись

Запустить (через PowerShell-инструмент, не Bash — скрипт вызывает `rsvars.bat`/`msbuild`,
которые нужны в реальном Windows-окружении):

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_release.ps1 -Config Release
```

Это выполнит: `msbuild GRUBer2.groupproj /t:Build /p:Config=Release /p:Platform=Win64x`,
считает фактическую версию из собранных `GRUBer.exe`/`DeviceLister.exe`
(`VersionInfo.FileVersion`), создаст папку релиза, скопирует оба exe и подпишет их
`signtool.exe`.

Стримить вывод пользователю по ходу выполнения. Если скрипт упал (billed build, отсутствующий
сертификат, ошибка signtool) — показать ошибку как есть, **не** докладывать об успешном
релизе и не переходить к шагу 4.

### 4. Итог

Сообщить пользователю финальный путь к папке релиза и список подписанных файлов, например:

```
Готово: D:\UsersFiles\JOB-PROJECTS\TEST\GRUBer-RELEASE\[GRUBer_0.3.5.4][DL_0.0.2.2][a1b2c3d]\
  - GRUBer.exe (подписан)
  - DeviceLister.exe (подписан)
```

## Как пользоваться

Вызов: наберите `/release-build` в сессии Claude Code внутри репозитория GRUBer2 (или просто
попросите "собери релиз" — скилл подхватится по описанию).

Что произойдёт:
1. Скилл проверит, нет ли незакоммиченных изменений — если есть, спросит, коммитить ли их.
2. Проверит, не отстаёт ли `origin` от локальной ветки — если да, спросит, пушить ли.
3. Соберёт обе программы в конфигурации Release/Win64x.
4. Скопирует готовые `GRUBer.exe` и `DeviceLister.exe` в новую папку в
   `D:\UsersFiles\JOB-PROJECTS\TEST\GRUBer-RELEASE\`, названную по версиям обеих программ и
   короткому хешу коммита, например `[GRUBer_0.3.5.4][DL_0.0.2.2][a1b2c3d]`.
5. Подпишет оба exe цифровой подписью.

На каждом из шагов 1–2 скилл может задать вопрос в чате — отвечайте выбором варианта.
Если сборка или подпись завершились с ошибкой, скилл остановится и покажет текст ошибки,
не создавая "релиз" из непроверенных файлов.

Предпосылки для машины, на которой запускается сборка:
- Установлена RAD Studio 37.0 (используется `rsvars.bat` из
  `C:\Program Files (x86)\Embarcadero\Studio\37.0\bin\`).
- В хранилище сертификатов Windows есть сертификат с thumbprint
  `B4D511E8418E0957521FE045EAAB39BA72B70F18`, и доступен
  `C:\Program Files (x86)\Microsoft SDKs\ClickOnce\SignTool\signtool.exe`.
- Есть сетевой доступ к `http://timestamp.digicert.com` (сервер штампа времени для подписи).

Если что-то из этого изменится (новая версия RAD Studio, другой сертификат, другой путь к
TEST-папке) — поправьте константы в начале `tools\build_release.ps1`.
